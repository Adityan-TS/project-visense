# ViSense — live captions on smart glasses

```
INMP441 ─I2S─> XIAO ESP32C3 ─IMA-ADPCM over BLE notify─> iPhone (on-device speech)
                    │                                        │
              SSD1306 OLED  <────── text over BLE write ─────┘
```

| Folder | What |
|---|---|
| `firmware/ViSenseMic/` | **Current build: OLED + INMP441 glasses mic.** Mic audio streams to the iPhone (pick "Glasses mic" in the app). Single file, needs only U8g2 |
| `firmware/ViSenseDisplay/` | Display-only glasses (no mic; the iPhone mic does the listening). Single file, needs only U8g2 |
| `firmware/MicTest/` | INMP441 wiring test: prints a live level bar + OK / NO DATA / STUCK |
| `firmware/ViSense/` | Older multi-file mic build (needs NimBLE-Arduino 2.x) |
| `firmware/DisplayTest/` | OLED wiring test: "Hello world" + I2C scan |
| `ios/` | SwiftUI iPhone app (iOS 17+), project generated by XcodeGen from `project.yml` |
| `tools/` | ADPCM round-trip test (firmware encoder ↔ iOS decoder) — `tools/run_tests.sh` |
| `docs/SETUP.md` | **One-time Mac setup: Xcode, Homebrew, XcodeGen, Arduino IDE** — start here |

The BLE protocol is defined once in `firmware/ViSense/visense_protocol.h` and mirrored in
`ios/ViSense/Protocol.swift`.

## 1. Wiring

| Part | Part pin | XIAO ESP32C3 pin | Notes |
|---|---|---|---|
| SSD1306 OLED | VCC | 3V3 | |
| | GND | GND | |
| | SDA | **D4** | I2C 400 kHz, address 0x3C |
| | SCL | **D5** | |
| INMP441 mic | VDD | 3V3 | **not** 5 V |
| | GND | GND | |
| | SCK | **D1** | I2S bit clock |
| | WS | **D2** | I2S word select |
| | SD | **D3** | I2S data |
| | L/R | GND | = left channel |

Never use **D0, D8, D9** (strapping pins). Power: USB-C.

## 2. Firmware (Arduino IDE)

1. Install the IDE, ESP32 core 3.x, **NimBLE-Arduino 2.x** and **U8g2** → `docs/SETUP.md` step 5.
2. Open `firmware/ViSense/ViSense.ino`.
3. Tools → Board → esp32 → **XIAO_ESP32C3**; Tools → **USB CDC On Boot: Enabled**; pick the port.
4. Upload. Serial Monitor at **115200**, line ending **Newline**.

All knobs are in `firmware/ViSense/config.h`:

| Setting | Default | Use |
|---|---|---|
| `ENABLE_BLE` / `ENABLE_MIC` | 1 / 1 | set 0 to isolate problems (Milestone 1 = both 0) |
| `DEBUG_SERIAL` | 1 | serial logs |
| `OLED_ROTATE_180`, `OLED_MIRROR_H` | 0, 0 | flip the image if the optics need it |
| `DEFAULT_FONT_SIZE` | 1 | 0 = 4×18 chars, 1 = 3×12, 2 = 2×9 |
| `MIC_GAIN_DEFAULT` | 10 | software gain (1 = unity); also changeable from the app |
| `MIC_USE_RIGHT_SLOT` | 0 | try 1 if the mic level stays 0 |
| `BLE_ENABLE_2M_PHY` | 1 | set 0 if `updatePhy` doesn't compile with your NimBLE version |

Serial commands: plain text = commit a line, `p:text` = live partial, `/clear`, `/demo`
(scrolling caption simulation), `/font 0|1|2`, `/gain N`, `/stat`.

## 3. iOS app: generate, sign, install (free Apple ID)

1. One time: Xcode + Apple ID in Xcode + `brew install xcodegen` → `docs/SETUP.md`.
2. Edit **`ios/Signing.xcconfig`**:
   - `DEVELOPMENT_TEAM = ABCDE12345`: your Personal Team ID. Find it in Xcode → Settings → Accounts → select the team, or let Xcode pick it in the Signing tab (step 4) and copy it from there.
   - `PRODUCT_BUNDLE_IDENTIFIER = com.yourname.visense`: must be unique to you.
3. Generate and open the project:
   ```bash
   cd ios && xcodegen generate && open ViSense.xcodeproj
   ```
4. In Xcode: select the **ViSense** target → *Signing & Capabilities* → check that "Automatically manage signing" is on and your Personal Team is selected. Fix any red errors here, usually the bundle ID.
5. Plug in the iPhone, unlock it, tap **Trust**. Pick it as the run destination at the top of Xcode → **▶ Run**.
6. First run only, on the iPhone:
   - **Developer Mode**: Settings → Privacy & Security → Developer Mode → On (the phone restarts).
   - **"Untrusted Developer"**: Settings → General → **VPN & Device Management** → your Apple ID → Trust.
7. Allow Bluetooth, Speech Recognition and Microphone when the app asks.

Free-account limits: the app **expires after 7 days** (just press Run again), max 3 sideloaded apps.
**Re-install the day before the hackathon.**

Re-run `xcodegen generate` whenever files are added or `project.yml` changes. The generated
`.xcodeproj` is git-ignored.

## 4. Milestones — how to test each one

| # | What | How to test |
|---|---|---|
| 1 | OLED + Serial | Set `ENABLE_BLE 0`, `ENABLE_MIC 0` in `config.h`, upload. Boot shows the captions screen. In Serial Monitor, type `hello world` (a committed line), `p:typing...` (live line), and `/demo` (auto-scrolling captions). Try `/font 0`, `/font 2`. |
| 2 | BLE text | `ENABLE_BLE 1`. OLED shows *"ViSense – waiting for phone"*. Open the app: the pill turns green "Connected" and the OLED shows *connected* plus a dot in the top-right corner. Test & debug → type text → **Send partial** / **Send final**. Change the S/M/L font. Tap **Clear**. Power-cycle the glasses: the app reconnects by itself. |
| 3 | Phone-mic fallback | Source **Phone mic** → **Start captions** → speak. Gray/white text in the app and on the OLED; after ~1 s of silence the line commits and scrolls up. Works without the glasses too. |
| 4 | Glasses audio | `ENABLE_MIC 1`. Plug **headphones** into the iPhone → Test & debug → **Monitor glasses mic**. You should hear yourself through the glasses mic, *Audio in* ≈ **50 pkt/s**, and the level meter moves. Adjust gain (around 8–16) until normal speech reaches about ⅔ of the meter. `/stat` on serial shows `fails=0`. |
| 5 | End to end | Source **Glasses mic** → Start → speak near the glasses → captions on the OLED. Unplug the glasses: a yellow "Using PHONE mic" note appears and captions continue; plug them back and it switches back. |
| 6 | Locked phone | Start captions → lock the phone → put it in a pocket → talk for 2 min → captions should keep coming. Unlock → Test & debug → Log shows `App -> foreground after N s: X partials, Y finals in background`. X > 0 means it worked. |
| 7 | Latency | Speak in short bursts with pauses. The status line shows `≈NNN ms (speech · BLE · OLED)`. Log lines `Latency: speech onset -> partial` show each sample. |

Round-trip test of the audio codec on the Mac (no hardware needed):

tools/run_tests.sh

## 5. Locked phone / background: how it works and what to verify

- `UIBackgroundModes = bluetooth-central, audio`.
- **Keep-alive:** the AVAudioEngine runs a **phone-mic input tap in every mode**, including *Glasses mic*, where its samples are thrown away unless auto-fallback kicks in. iOS does not suspend an app that is actively recording with the `audio` background mode, and the Speech framework keeps serving it. Downside: the orange mic dot shows. This was chosen over the "play silent audio" trick because recording is the state Speech is designed to work in.
- BLE: a pending `connect()` never times out, also in the background. CoreBluetooth state restoration (`visense.central`) brings the link back if iOS relaunches the app.
- Recognizer: tasks rotate on every pause (`pauseCommit`, 1 s), on recognizer finals and errors (with back-off), and every 55 s. Audio that arrives while no task exists is buffered (up to 5 s) and fed to the next task, so nothing is lost.
- **Verified on a real iPhone (Nov 9):** captions keep running with the phone **locked** and with the app
  **in the background** (home screen / other app), as long as the app stays in the app switcher.
- **Not possible: swiping the app away (force-quit) stops everything.** This is an iOS rule for every
  third-party app. A force-quit app doesn't get relaunched for Bluetooth or audio, and an app can't start
  recording from the background. Same after a phone reboot: open ViSense once and tap Start.
  **Demo rule: start captions, then just lock the phone. Never swipe ViSense away.**
- Other things that can stop it: Low Power Mode (sometimes), a phone call (the audio session resumes after the call).

## 6. Latency budget (target < 400 ms)

| Stage | Expected | Knob |
|---|---|---|
| Audio frame on the glasses | 20 ms | `VS_AUDIO_FRAME_SAMPLES` |
| BLE uplink | 15–30 ms | connection interval 15–30 ms (`updateConnParams` in `ble.cpp`) |
| Speech onset → first partial | 150–350 ms | on-device model (`requiresOnDeviceRecognition`); most of the budget |
| Partial throttle | 0–100 ms | `partialInterval` in `CaptionController` |
| BLE downlink | 15–30 ms | same connection interval |
| OLED redraw | ~25 ms | I2C 400 kHz, full-buffer draw |

"Commit line after X s pause" (Test & debug) changes how fast a line gets committed. It does not affect the latency of the live partial line.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| Serial Monitor empty | Tools → USB CDC On Boot → **Enabled**; baud 115200. |
| Upload fails / board not found | Hold **BOOT**, tap **RESET**, release BOOT, then upload. Use a data USB cable, not a charge-only one. |
| OLED blank | Check SDA=D4 / SCL=D5 and 3V3 power. Some modules use address 0x3D: change `OLED_I2C_ADDR`. Run an I2C scanner sketch. |
| Image upside down / mirrored | `OLED_ROTATE_180` / `OLED_MIRROR_H` in `config.h`. |
| Compile error at `updatePhy` | `BLE_ENABLE_2M_PHY 0`. |
| Compile errors in `ble.cpp` mentioning `NimBLEConnInfo` | You have NimBLE-Arduino 1.x. Install **2.x** in Library Manager. |
| Compile errors about `ESP_I2S.h` | You have ESP32 core 2.x. Install **3.x** in Boards Manager. |
| App never finds the glasses | Bluetooth on? The OLED should show "waiting for phone". In the iOS Settings app the glasses must **not** appear as a paired device (we don't pair). Kill and reopen the app. Check that the UUIDs in both protocol files match. |
| Mic level stays 0 / `mic ok` false | Check wiring (SD=D3, WS=D2, SCK=D1, L/R=GND, VDD=3V3). Then try `MIC_USE_RIGHT_SLOT 1`. |
| Audio sounds distorted | Gain too high: lower it with the app's gain stepper or `/gain 6`. |
| Audio in < 50 pkt/s, "fails" rising | RF trouble: keep the antenna clear of metal and the phone closer. Check the MTU in the app: it should be ≥ 168. |
| "recognizer unavailable" | No on-device model for the language: Settings → General → Keyboard → Dictation on, with the language downloaded. The default locale is `en-US` in `SpeechEngine.init`. |
| Speech says "server, 1-min limit" | That phone/language has no on-device recognition. It still works (rotates every 55 s) but needs internet. |
| App won't launch: "Untrusted Developer" | Settings → General → VPN & Device Management → Trust. |
| App stopped working after a week | Free-account profile expired. Run it from Xcode again. |
| Captions stop when the phone is locked | See section 5. Check the Log after unlocking. |
| Feedback squeal when monitoring | Use headphones. The monitor plays the glasses mic through the phone. |

## 8. Databricks: conversation memory + Ask agent

| Piece | Where |
|---|---|
| Workspace | `https://dbc-2a25625f-05c4.cloud.databricks.com` (hard-coded in `DatabricksClient.swift`) |
| Model | `workspace.default.visense-chat` (gpt-oss-120b via AI Gateway, reasoning effort low) |
| Tables | `workspace.visense.users`, `workspace.visense.transcripts` (`databricks/setup.sql`) |
| SQL | Serverless Starter Warehouse, via the SQL Statement Execution API |
| Secrets | `ios/Secrets.xcconfig` (git-ignored): `DATABRICKS_TOKEN`, `DATABRICKS_WAREHOUSE_ID` |

**App tabs**
- **Captions**: live captions to the glasses. Every finished line is queued and uploaded (batched, retried, no duplicates).
- **History**: all conversations from Databricks, grouped by day. Pull down to refresh, tap one for the full timestamped transcript and "Ask about this conversation".
- **Ask**: chatbot. The model picks a time window from the question (e.g. "convo at 3 PM" -> 14:58-15:08), the app runs a fixed SQL query for *this user's rows only*, and the model answers from those lines.

**Setup / check from the Mac:** `python3 -I databricks/setup_and_test.py` creates the schema + tables and runs an end-to-end test (inserts a test user, queries, asks the model, deletes the test data).

**After the hackathon:** delete the access token in Databricks (it is compiled into the app).
